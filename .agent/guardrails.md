# guardrails — 禁止事項と、その理由と、強制の仕組み

> **人間だけが編集する。**
> このファイルの文章は「お願い」でしかない。本当に守らせたいものは、右端の列の仕組みで機械的に強制している。
> 文章の役割は、**なぜ禁止なのかを伝えて、最初から違反しにくくすること**。

| # | 禁止事項 | 理由 | 強制の仕組み |
| --- | --- | --- | --- |
| G1 | 承認済みの `claims.md`・`targets.json`・`tests/*/claims/` を編集する | 完了の定義を自分で書き換えると、ループが「合格」を捏造できてしまう | check.py のロック検査（全エージェント）、guard.py フック（Claude Code） |
| G2 | `runs/` を手で作る・直す・消す | 結果は事実の記録。直せる結果には価値がない | check.py の結果の改変検査（INDEX.jsonl のハッシュ）、guard.py |
| G3 | `scripts/lock.py`・`scripts/adapt_mode.py` を実行する | 承認と保護の解除は人間の仕事。自分でやったら意味がない | guard.py、`.claude/settings.json` の deny |
| G4 | 許容誤差や目標値を変える、変えるよう誘導する | G1 と同じ | G1 と同じ |
| G5 | 論文に書かれていない選択を、記録せずに行う | 再現しない時に疑う場所が分からなくなる。再現性はここで一番失われる | なし（文章だけ）。フェーズ5 で decisions.md を見直す |
| G6 | 実験で一度に2つ以上を変える | どれが効いたのか分からなくなる | run.py が `parent` の run と params を比べ、2つ以上違えば実行を拒否（コードの変更は検出できないので、そこは文章だけ） |
| G7 | 失敗理由を書かずに直し始める | 次の周回・次のセッションで同じ失敗を繰り返す（ガチャになる） | check.py の出力が毎回書くよう指示する |
| G8 | `core/` に入出力・乱数の生成・他の層への依存を持ち込む | 性質のテストが速く決定的に書けなくなる | check.py の依存方向の検査 |
| G9 | `paper.md`・`goal.md`・`scripts/`・`lab.config.json` を編集する（ADAPT 中を除く） | 入力と仕組みを変えると、結果の意味が変わる | guard.py |
| G10 | 予算を超えて回し続ける | 直せない問題の前で永久に回り、コストが溶ける | run.py が `budget` の試行数・診断数を超える実験を拒否。ハーネスのターン上限（`/goal` など） |
| G11 | 予測を書かずに試行する・外れた仮説を言い換えて出し直す | 予測が無いと「仮説が否定された」と判定できず、同じ方向の微調整が続く | run.py が prediction・falsified_if の無い試行を拒否。予測が続けて外れた型は排除し、新しい診断実験を `based_on` にしない限り拒否 |
| G12 | 停滞しているのに、試した型の微調整を続ける | 局所解から抜け出せない。前の周の反省だけを入力にすると方向が変わらない | ledger.py が停滞を検知して探索モードにし、run.py が試した型の試行を拒否 |
| G13 | 仮説の型を勝手に作る・Reviewer の基準を変える | 型を言い換えれば排除をすり抜けられる。Reviewer を緩めれば自己承認になる | 型の一覧は `lab.config.json`（guard.py で保護）にあり run.py が照合。`REVIEWER.md`・`.claude/agents/` は guard.py で保護 |
| G14 | ばらつきで決まった結果から次の仮説を立てる | ノイズを手がかりと取り違え、誤った方向に積み上がる | compare.py がブートストラップ区間で「判定不能」を返す（終了コード 3） |

## 強制の仕組みの限界（正直に）

* **guard.py は Claude Code のフックでだけ動く。** Hermes など他のエージェントでは、改変は防げず、
  check.py が**後から検出する**だけになる。検出されたら元に戻させる
* guard.py のシェルコマンド検査は文字列の照合なので、書き方次第ですり抜けうる。
  すり抜けた改変も check.py のハッシュ検査で検出される
* check.py 自体（`scripts/`）を書き換えられたら、すべての検査が無効になる。
  `scripts/` は guard.py で守っているが、他のエージェントでは git の差分で人間が確認すること
* 仮説の**型**は自己申告。中身が「未確定点の解釈」なのに型を「実験条件」と書けば、排除をすり抜けられる。
  run.py はこれを見抜けないので、Reviewer と人間が台帳（`ledger.py`）と `runs/<run>/config.json` の text を見比べて確認する
* 「探索モードに入ったら Reviewer を呼ぶ」は文章だけで、呼んだかどうかは `journal/reviews/` にファイルがあるかで人間が確認する。
  Reviewer が読むだけに留まるのも指示による（Claude Code では guard.py が保護された場所への書き込みを止める）
* 停滞の判定（`explore` の設定値）が粗すぎても細かすぎても、探索モードが早すぎたり遅すぎたりする。題材に合わせて人間が調整する
