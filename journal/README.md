# journal — 記録室

人間が後から読むための研究ノート。エージェントが**追記だけ**する。

| ファイル | 内容 |
| --- | --- |
| `decisions.md` | 資料に書かれていない点の解釈（D番号）、キットの組み替え（K番号） |
| `YYYY-MM-DD.md` | その日のセッションの記録（下の書式） |
| `reviews/` | Reviewer の報告（`.agent/REVIEWER.md`）。受け取ったまま保存し、編集しない |

`progress.md` との違い：progress.md は**現在地**（上書きされる）、journal は**経緯**（積み上がる）。

## 日ごとのノートの書式

```markdown
# YYYY-MM-DD

## <題材> <主張ID>（モード: 通常 / 探索）
- 仮説: <この周で何を確かめたか。変えたものは1つだけ>（型: <hypothesis.type>、親: <parent>）
- 予測: <実行前に書いた prediction>。外れたら: <falsified_if>
- 実験: experiments/<名前>/<ファイル>.json → runs/<フォルダ>
- 結果: <compare の出力をそのまま>
- 予測の当否: 的中 / 外れ / 判定不能
- 解釈: <なぜそうなったと考えるか。外れたなら、何を捨てたか>
- 次: <次に変える1つ。探索モードなら、未試行の型・診断実験・Reviewer のどれを選んだか>

## セッションの要約
- 進んだこと / 止まった理由 / 人間に判断してほしいこと
```
